## 2판 → 3판 바뀌는 점(요약)

1. 이야기 카드 = **요약(사슬 한 줄) → 결론(자동 조사) → 조치(권장 단추) → 자세히(탭 하나씩)**.
2. 카드 안에 카드를 넣지 않는다. 같은 모양의 반복은 카드 하나 + "발생 N번" 탭.
3. 카드에 "지금 상태" 줄(실행 중 / 끝남 / 확인 못 함).
4. 새 의심 사건 Windows 알림(창을 닫아도, 기본 켬) — 2판의 조용함 원칙 예외를 넓힘.
5. 흐름 보기의 "프로그램 자세히"는 좁은 옆 칸이 아니라 넓은 오른쪽 서랍(3-7 상세)으로 연다.

## 2-9. 같은 판정 묶음 (바뀜)

- 묶음 기준은 2판 그대로(같은 실행 파일 경로 + 서명 + 판정 규칙).
- 제목 칩 "N건" → **"N번"**(같은 모양이 N번 일어남). 제목 아래 회색 한 줄 "같은 모양 N번 · 처음 ~ 마지막".
- "발생 시각" 접힘 목록과 "이 사건 보기"(카드 안 카드)를 없앤다. 대신 자세히 탭 **"발생 N번"**: 줄마다
  시각 · 그 발생의 지금 상태 · 접속지(나라) · [이 발생의 흐름](그 자리에 흐름 보기만).
- 대시보드·다른 화면에서 묶인 사건으로 이동하면 그 카드의 "발생 N번" 탭을 열고 그 줄을 강조(2-11).

## 3-2. 오늘의 이야기 — 사건 카드 (바뀜)

```
[수준] 부모 → 주인공 → 실행한 프로그램(최대 3 + "외 N")  [N번]          마지막 활동 시각
       같은 모양 N번 · 처음 ~ 마지막            (묶음일 때)
       ● 지금도 실행 중 (PID n) | 지금은 끝남 (PID n) | 지금 상태 확인 못 함 (PID n)
       4칸 진행 · (파괴 징후 줄)
 ┌ 결론 ───────────────────────────────────────────────────────────────┐
 │ 권장: … · 판단 한 문장(사실만)                                       │
 │ ✓ / ✗ / · 확인한 사실 (지금 상태·경로·명령줄·부모·서명·등록 등)      │
 └──────────────────────────────────────────────────────────────────────┘
 자세히 [사실] [흐름 보기] [마인드맵] [발생 N번]        [이건 정상입니다] [여기서부터 끊기…]
 (누른 탭 하나만 아래 전체 폭으로)
```

- **제목(요약)**: 부모와 자식은 회색, 주인공은 굵게. 주인공 이름은 버튼(3-7 프로그램 상세). 전체 사슬은 툴팁.
  한 줄이 넘치면 말줄임(툴팁에 전체).
- **접속 줄**(검수 반영): 접속지가 있으면 제목 아래 "접속: 주소:포트 (나라 · 조직)" — 자세히를 열지 않아도 어디에
  접속했는지 보이게.
- **지금 상태 줄**: 시각을 넣지 않는다(시각은 오른쪽 위 마지막 활동 하나). 실행 중이면 --brand 점·글씨,
  아니면 --muted. "확인 못 함"의 이유는 툴팁("끝난 기록이 없고, 같은 번호(PID)로 떠 있는 프로세스가 같은
  프로그램인지 확인되지 않았습니다"). 단정 금지: 모르면 "실행 중 아님"이라고 쓰지 않는다.
- **결론(자동 조사)**: 서비스 story.investigate 결과. 첫 줄 = "권장: …" + 판단 한 문장. 펼치면 사실 목록.
  - 권장 문장 세 가지: "권장: 알려진 정상 모양 — 끊지 마세요" / "권장: 여기서부터 끊기" /
    "권장: 아래 사실을 보고 정하세요". 확신 말("보입니다")은 쓰지 않는다(D028-1).
  - 테두리: 알려진 정상 모양 = --brand, 위험 = --bad, 모름 = --line. 모름이면 닫힌 채로.
  - 파괴 징후(5장)가 있고 정상 모양으로 확인되지 않으면 "끊기"를 권한다.
  - 닫혀 있어도 의심 쪽 사실(✗) 두 개까지는 첫 줄 뒤에 붙인다. "지금 상태"는 머리 줄에 있으니 결론 사실에서 뺀다.
    파괴 징후가 있으면 그 명령줄을 사실 맨 앞에(직접 근거).
  - 사실 표시: ✓(정상 쪽 근거, --ok) ✗(의심 쪽 근거, --bad) ·(정보·확인 못 함). 경로·명령줄·등록 이름은
    외부 문자열 — 자료로만 표시(제어·방향 바꿈 문자 제거, 길이 제한).
- **조치 단추**: 2-4·D1 순서 그대로 — 보조(자세히 탭) 왼쪽 → 주(이건 정상입니다) → 파괴적(여기서부터
  끊기…, 빨간 테두리) 오른쪽 끝. **빨간 채움 단추 0**. 권장 조치가 정상이면 "이건 정상입니다"를 주 단추(채움),
  끊기면 끊기 단추 테두리를 굵게 + "권장 · " 앞붙임.
- **자세히 탭**: 사실(2판 본문 항목·근거 배지·위치·서명·🕒/⚠ 줄) / 흐름 보기 / 마인드맵 / 발생 N번. 한 번에
  하나만 열리고, 다시 누르면 닫힌다. 기본은 모두 닫힘.
- 안내 줄은 카드에 한 번만, 단추 줄 바로 아래(탭 패널이 열려도 떨어지지 않게). 문구 "이 종류의 사건(프로그램이
  실행 중에 시작한 사건)은 아직 '정상'으로 표시하는 기능이 없습니다."(개발 말 "예외 단위 준비 중" 대체).

## 3-6. 설정 (추가)

- "알림" 절: [✓] 새 의심 사건을 Windows 알림으로 알리기(기본). 설명 "앱 창을 닫아 두어도(트레이) 사건이 한 장
  더 나아갈 때마다 한 번 알립니다. 원격 제어 시작 알림은 이 설정과 상관없이 늘 뜹니다."
- 알림 문장: 제목 "의심 사건: <프로그램 이름>", 본문 "<N장 이름>까지 이어졌습니다. 트레이 아이콘을 눌러
  '이야기'에서 확인하세요." 의도를 단정하지 않는다.

## 3-7. 프로그램 상세 (바뀜)

- 흐름 보기의 "프로그램 자세히"도 오른쪽 서랍으로 연다(옆 칸 안에 넣지 않는다 — 좁아서 한 단어씩 줄바꿈).

## 3-8. 사건 추적 (추가, 2026-11-07 구현)

- 처리 상태: **새 사건 → 조사됨 → 조치함(정상·끊음·지켜보기) → 닫힘**. 서비스 `story.triage`(조회 권한, DB 쓰기는 상태가
  바뀔 때만), `story.triage_log`(처리 기록, 최신 먼저). `story.events` 가 카드마다 `triage` 를 붙이고 `counts` 를 준다.
- 카드 제목 줄: 수준 칩 다음에 **처리 상태 칩**. 새 사건=테두리만, 조사됨=회색, 조치함=초록("조치함 · 지켜보기"처럼 조치
  종류까지), 닫힘=연회색. 툴팁에 바뀐 시각·메모.
- 상태가 바뀌는 때: 자동 조사가 끝난 새 사건은 **조사됨**(화면이 한 번 보고). "이건 정상입니다" 성공 → **조치함 · 정상**,
  "여기서부터 끊기" 성공 → **조치함 · 끊음**(서비스가 스스로 적음). 단추 "지켜보기" → 조치함 · 지켜보기, "닫기" → 닫힘
  (닫는 이유 메모 선택, 200자).
- 툴바에 "처리 상태" 필터: **처리 안 한 사건(기본)** / 처리한 사건 / 전부. 그 아래 한 줄 "처리 안 한 사건 N (새 사건 N ·
  조사됨 N) · 조치함 N · 닫힘 N". 처리 안 한 사건이 0 이고 처리한 사건이 있으면 빈 문구가 그 수와 고르는 법을 말한다.
- 단추 줄: 자세히 탭에 **처리 기록**(새 사건이 아닐 때만). 지켜보기·닫기는 보조 단추, 정상·끊기는 지금 자리 그대로.
- 대시보드 카드 제목 "처리 안 한 의심 사건"(조치함·닫힘은 세지 않음). 알림(Windows·앱)은 처리 안 한 사건만.
- **재발**: 조치함·닫힘인 사건이 조치 시점보다 **높은 장**까지 이어지면 주기 판정이 새 사건으로 되돌리고 처리 기록에
  "재발: N장에서 조치했는데 M장까지 이어짐"(자동)을 남기며 다시 알린다. 같은 장의 반복(같은 접속 N번)은 재발로 보지 않는다.
- 보관: 처리 기록 1년, 뿌리가 지워진 상태 행은 보관 정리 때 함께 지움.

## 3-9. 프로세스에서 시작한 사건의 "이건 정상입니다" (추가, 2026-11-07 구현)

- 대상: (다) 고립 svchost · (라) 문서 처리기 → LOLBin · (바) 복구 수단 삭제. (사) 금고 경비는 3판 이전 방식(그 판정 키) 그대로.
- 정상 단위 = **부모 프로그램 → 실행된 도구(뿌리) → 그 도구가 띄운 프로그램들**, 각각 경로 + 서명(파일 뿌리와 같은 키).
  (바)는 **명령 종류**("그림자 복사본 삭제" 등)까지 단위에 넣는다. 도구 자체(cmd·powershell·vssadmin)는 정상이 되지 않는다.
- 단추를 누르면 먼저 확인 창: "이 실행 조합만 정상으로 봅니다: `winword.exe → powershell.exe → (curl.exe)` ·
  실행한 프로그램이나 띄우는 프로그램이 달라지면 다시 의심합니다. 도구 자체를 정상으로 만들지는 않습니다." 확인해야 보낸다.
- 성공하면 처리 상태 **조치함 · 정상**, 처리 기록에 "정상 조합: …" 한 줄. 카드 안내 줄(FEEDBACK_NOT_YET)은 이 세 종류에서 사라진다.
- 다시 의심하는 때: 같은 도구가 **다른 프로그램을 더 띄우거나**, 부모가 달라지거나, (바)에서 다른 파괴 명령을 실행하면
  조합 키가 달라져 새 사건으로 판정한다(처리 기록은 남음).
- 조합은 판정과 같은 그래프 창(주기 판정 뷰)에서 만든다. 뷰가 아직 없으면 "지금 확인할 수 없습니다 · 잠시 뒤" 오류.
