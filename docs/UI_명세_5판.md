# UI 명세 (5판) — 확정 (2026-11-11, 사용자 "나중에 정해도 됨은 모두 추천으로")

바탕: UI 명세 4판(확정 2026-11-09). 이 판은 **4판에서 바뀌는 것만** 적는다. 적지 않은 장은 4판(그리고 4판이 가리키는 2판·3판 초안) 그대로.
근거: 화면 검수(2026-11-11, 별도 검수 에이전트, 캡처 7장, 12항목), 차단 기록 기능 추가(사용자 요청 2026-11-09 "차단 리스트가 별도로 있어야겠음, 차단된 이유를 쉽게 추적").

## 1. 차단 기록의 자리 (4판 3-2 수정)

- 차단 기록은 **네트워크 › 차단 기록** 탭(지금 열린 연결 · 연결 이력 · 차단 기록)에 둔다.
  - 이유: 차단 기록에는 우리 정책뿐 아니라 Windows 방화벽·서비스 보호·앱 격리 등 모든 WFP 공급자의 차단이 들어간다.
    정책 화면 아래에 두면 "Story Firewall 이 막았다"로 읽힌다(2판 원칙 1 단정 금지). 사용자는 브라우저 차단 화면을 보고 연결 문제로 찾아온다.
  - 4판 3-2 의 "KPI 오늘 차단 통신 → 정책 › 차단 기록 {range: today}" 은 **네트워크 › 차단 기록 {range: today}** 로 바꾼다.
- 정책 화면: 우리 정책마다 "이 정책으로 막힌 기록 N건 ›" 링크 → 네트워크 › 차단 기록을 그 규칙으로 걸러 연다.

## 2. 엔진이 바쁠 때 (2판 2-5 구체화)

- 화면의 칸마다 **마지막으로 받은 값**을 유지하고, 위에 "엔진이 바빠 h:mm 에 받은 값을 보여 줍니다" 한 줄(--warn).
- 처음부터 받지 못한 값은 0 이 아니라 "—" 또는 2-5 "불러오는 중 — 엔진 바쁨"(원칙 6).
- 이미 그린 화면은 다시 불러오는 동안 지우지 않는다.
- 공통 상단 띠도 같은 규칙: 모르는 정책 수는 "정책 —". 긴급 차단 단추는 엔진이 바빠도 늘 누를 수 있다(대화상자 안에서 "반영이 늦을 수 있음").

## 3. 통신 대상 분포 카드 (4판·대시보드 개편안 보완)

- 머리말: "오늘 연결 N건 · 상대 주소 많은 순 500곳 기준"(막대 숫자 = 연결 건수, 500 = 상대 주소 수 상한을 구별).
- 막대 수: 명세대로 **상위 8 + 그 밖에 N개 나라/망**.
- 오늘 / 지금 열린 연결 토글과 막대 / 지도 분절은 어떤 상태에서도 그린다.

## 4. 대시보드 숫자의 기준 맞추기 (검수 5번)

- "심각도별 미조치 인시던트"와 "우선 대응 인시던트" 목록은 같은 조회·같은 필터(처리 안 한 것, 높음 이상)를 쓴다.
  기준(기간·처리 상태)이 다르면 그 기준을 칸 머리에 쓴다. 받지 못한 값으로 0 을 그리지 않는다.

## 5. 구현 순서(짧은 순환)

1. 엔진 바쁨 때 직전 값 유지·분포 카드 다시 그리기 버그·분포 머리말 — **완료(dd2aa7e, install-166)**
2. 엔진: 판정 뒤 정리를 미뤄 화면 요청 먼저 — **완료(b37de66, install-168)**
3. 대시보드 숫자 기준 맞추기(4장)
4. 분포 막대 상위 8(3장)
5. 상단 띠 바쁨 규칙(2장 끝)
6. 차단 기록: 정책 화면 링크 + KPI 오늘 차단 통신(1장)
7. 차단 기록 첫 화면: "오늘 차단 N건 · 마지막 h:mm" 머리 + 설명 접힘(검수 11번)
8. 지금 열린 연결 탭 열·정렬을 4판 3-4 에 맞춤(검수 10번)

각 순환: 별도 검수 에이전트가 캡처를 이 문서와 대조.
