# 47차 검증 답변 반영 (2026-11-11)

대상: 검증의뢰서 47차 — 판정 소음 줄이기(Local State·분리 svchost). 답변: Gemini.

| 항목 | 판단 | 반영 |
| --- | --- | --- |
| Q1 Local State + 권한 상승 서비스 결합 | **수용** | 한 이야기에 "브라우저 설정(Local State)을 엶"과 권한 상승 서비스 신호("브라우저가 아닌 프로그램이 브라우저 권한 상승 서비스를 실행" 또는 "브라우저 종료 직후 권한 상승 서비스 시작")가 함께 있으면 결정적 근거로 본다. 테스트: 서명 없는 프로그램이 Local State + 권한 상승 서비스 + 외부 접속 → 심각 |
| Q2-1 부모 위장(PPID spoofing) | **수용, 방법은 일부 반박** | 답변이 권한 "토큰 대조"는 쓰지 않는다: 부모 위장으로 띄운 자식은 위장된 부모(services.exe, SYSTEM)의 토큰을 물려받아 토큰으로는 구별되지 않는다. 대신 Kernel-Process 시작 사건의 헤더 PID(실제로 만든 프로세스)와 부모 PID 를 대조한다. 다르면 svchost 서비스 이름을 읽지 않는다(믿지 않는 쪽으로 닫힘), 카운터 `svchost_parent_mismatch`. 참고: services.exe 는 보호 프로세스(PPL)라 보호되지 않은 프로세스가 부모로 지정할 핸들을 얻기 어렵다 — 추가 방어선이며, 헤더 대조는 그와 별개로 둔다 |
| Q2-2 ServiceDll 레지스트리 변조 | **수용(범위 밖)** | 관리자 권한 탈취 뒤의 변조는 사용자 모드 방화벽 범위 밖으로 둔다 |
| Q2-3 svchost 에 나중에 코드 주입 | **수용** | 기존 설계(새 외부 접속 시점의 메모리 검사)로 둔다 |
| Q3 PID 재사용으로 명령줄이 엉뚱한 프로세스에 붙음 | **수용(실제 구멍 확인)** | 만남 장소가 PID 만으로 짝짓고 있었다. 이제 커널 사건 시각과 CreateTime 이 1초 안이어야 짝짓는다. 답변의 100ms 는 받지 않는다: 커널 사건 시각은 QPC→벽시계 변환값이라 시각 변경·변환 오차에 깨질 수 있다. 버린 수는 `cmdline_time_mismatch` 로 세어 실측 뒤 좁힌다. 직접 읽기 경로는 원래 GetProcessTimes 정확 일치 |
| Q4 -k 그룹 대응표 | **수용(도입 안 함)** | 공유 호스트는 SCM 폴링에만 의존 |

검증(노트북): 설치 뒤 서비스 기록 `collector: counts` 에서 `svchost_parent_mismatch=0`(정상 PC), `cmdline_time_mismatch` 값, 새 분리 svchost 의 service_arg 가 계속 붙는지 확인.
