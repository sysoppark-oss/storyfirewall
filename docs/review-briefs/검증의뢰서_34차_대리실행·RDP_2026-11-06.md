# 검증 의뢰서 34차 — 변경 장부 대리 실행 잇기·RDP 세션 감지 (2026-11-06)

대상: Story Firewall 제품 A. 공개 저장소 `sysoppark-oss/storyfirewall` (AGPL-3.0).
33차 답변 반영(L079: 장부 pid+생성 시각·폴더 묶기, 해시 못 얻은 재실행 다시 관찰, 원격 알림은 사용자 표시로만 낮춤) 뒤 두 가지를 더했다. 아래 설계가 **깨지는 입력·순서**를 먼저 적어 달라.

## 1. 바뀐 것

| 번호 | 내용 |
| --- | --- |
| L080 | 변경 장부 대리 실행 잇기(33차 Q1). 관찰 대상(또는 자손)이 schtasks·at·wmic·sc 를 띄우면 그 종류의 "대리 창"을 2분 연다. 창이 열린 동안 작업 스케줄러(svchost·taskhostw)·WmiPrvSE·services 가 새로 띄운 프로세스를 최대 3개까지 장부에 "시각으로 이음"으로 물려준다. 그 파일은 출처에 뿌리(대상 pid@생성 시각) 꼬리표를 달고, 조회는 관찰 기간 안에서 꼬리표로 찾는다 |
| L081 | 원격 제어 경보에 원격 데스크톱(RDP) 세션 감지(32차 Q1). 서비스가 10초마다 WTSEnumerateSessionsW 로 활성 세션 중 접속 방식이 RDP(WTSClientProtocolType=2)인 것을 보고, 새로 생기면 경보(3), 사라지면 끝 사건(그동안 일어난 일 한 줄). 접속한 쪽 컴퓨터 이름은 문장에 사실로만 붙인다. 사용자가 "내가 쓰는 원격 도구"에 rdp 를 넣으면 작게(2) |

## 2. 질문 (공격자 관점 먼저)

**Q1 (L080 창 피하기)**: 창은 도구 실행이 보일 때만 열린다. 대상이 `schtasks.exe` 대신 COM(ITaskService)·PowerShell `Register-ScheduledTask`·`Start-ScheduledTask`, WMI COM 직접 호출, `sc.exe` 대신 `New-Service` 를 쓰면 창이 안 열린다. 도구 실행 말고 드라이버 없이 볼 수 있는 신호(예: 작업 스케줄러 Operational 로그 106·200, 서비스 제어 관리자 7045, WMI-Activity 로그)를 순서대로 적어 달라 — 어느 것이 실시간에 가깝고 어느 것이 대상 프로세스와 이어질 근거(호출자 pid 등)를 주는지.

**Q2 (L080 창 오염)**: svchost 는 여럿이고 늘 무언가를 띄운다. 공격자가 아니라 우연히 같은 2분 안에 Windows 업데이트·백신 검사가 svchost 아래에서 프로그램을 띄우면 장부에 남의 파일이 적힌다. 창을 svchost 전체가 아니라 작업 스케줄러 서비스(Schedule)를 담은 svchost 로 좁히는 방법(서비스 대조표)과 그때 남는 오탐.

**Q3 (L081 RDP 피하기)**: WTS 로 보는 것은 "활성 RDP 세션"이다. RDP 섀도(관리자가 콘솔 세션을 몰래 보기), RemoteApp, 세션 상태가 Connected 지만 Active 가 아닌 순간, 콘솔 세션으로 다시 붙기(tscon) 같은 순서로 경보를 피할 수 있는가. 그리고 들어오는 3389 연결 자체(수집기는 지금 들어오는 연결 선이 없음)를 쓰지 않는 것이 맞는가.

**Q4 (L081 이름 위장)**: 접속한 쪽 컴퓨터 이름은 접속하는 쪽이 정한다. "고객센터" 같은 이름으로 경보 문장을 안심시키는 데 쓰일 수 있다. 이름을 아예 빼는 쪽과 "접속한 쪽이 알린 이름"이라고 밝혀 두는 쪽 중 어느 것이 나은가.

## 3. 확인된 것
- 시험: 대리 창(열림 전엔 안 이음, 같은 종류만, 개수 3, 시간 지나면 닫힘), 뿌리 꼬리표로 파일 찾기(앞자리만 같은 다른 뿌리 제외, 기간 밖 제외), RDP 세션 비교(시작·유지·끝, 끝 문장의 분).
- 노트북 실측: 설치 뒤 진단에서 WTS 조회 2ms, 지금 RDP 세션 0(TeamViewer 세션은 RDP 아님), 판정 0.7초·이야기 조회 0.35초.
