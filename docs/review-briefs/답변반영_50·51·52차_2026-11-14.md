# 답변 반영 — 50·51·52차 (Gemini 답변 2026-11-14)

수용 = 고침/고칠 것, 반박 = 근거를 적고 안 고침, 검증 = 더 봐야 함.

## 52차
- **Q2 선을 못 찾으면 보임 → 수용(고침).** 뿌리가 보이는 사건(자기 세션·세션 0)에 다른 사용자 프로세스가 끝인 선이 들어 있다가 그 선만 정리되면,
  미리 만든 문장이 남은 채 사건이 보일 수 있다. `Scope::edges_visible`·`StoryVisibility::compute_with`·`story_today` 세 곳을 "못 찾으면 숨김"으로 뒤집었다.
  시험: `story_with_unverifiable_edge_is_hidden_from_users`. 대가: 보관 정리 직후 다음 판정까지 일반 사용자 목록에서 그 사건이 잠깐 빠진다(관리자는 그대로).
- **Q1 세션 0 으로 굳음 → 반박.** 세션은 Kernel-Process 시작 기록의 SessionID 또는 스냅숏 때 OS 조회(session_of)에서만 온다. 수집기가 "잠깐 0"을 쓰는 경로가 없고,
  못 얻으면 비워 둔다(= 모름 → 숨김). Gemini 도 근거 문서를 대지 못했다. 다만 세션 0 서비스가 사용자 세션에 자식을 띄우는 경우는 자식 노드의 세션으로 가려진다(52차 Q2 고침과 맞물림).
- **Q3 OpenProcess 권한 → 반박(이미 그렇게 함).** `PROCESS_QUERY_LIMITED_INFORMATION` 으로 연다(win/process.rs create_time, authn.rs). 서비스는 SYSTEM 이다.
- **Q4 → 동의.** 바꿀 것 없음.
- **Q5 정책 번호 재사용 → 반박.** 정책 행은 지우지 않는다(코드에 `DELETE FROM policies` 없음, 되돌려도 행은 남는다). 필터 → 정책 짝은 지금 걸린 필터 표(wfp_filters)로만 찾는다.

## 50차 (52차 구현 기준)
- **Q1 조치 뒤 낡은 상태 → 반박.** 처리 상태는 스냅숏이 아니라 조회 때 DB 에서 읽는다(triage::all). 조치 직후 조회에 바로 반영된다.
- **Q2 포트 재사용으로 엉뚱한 연결 끊기 → 반박.** 연결 끊기는 사건 목록(스냅숏)이 아니라 "지금 열린 연결"(OS 연결 표)에서 하고, 실행 직전에 5-튜플 + PID 가 지금도 같은지 다시 본다.
  같은 PID 가 같은 로컬 포트로 같은 원격 주소·포트에 다시 붙은 경우만 남는데, 그것은 사용자가 고른 바로 그 상대와의 연결이다.
- **Q3 작업자 분리 → 수용(다음 수정).** 조회 한 건 6초 상한·대기 16건 상한이 있지만, 여러 연결에서 넓은 범위 연결 목록을 계속 보내면 이야기 목록이 같이 늦는다.
  이야기 목록(스냅숏) 작업자와 DB 조회 작업자를 나눈다.
- **Q4 캐시 크기 → 반박(이미 상한).** 4,096칸 상한 + 10분 수명(NARR_CAP·NARR_TTL_SECS). LRU 크레이트는 들이지 않는다.
- **Q5 네거티브 캐시 → 반박.** 세션 모르는 노드는 조회 한 번에 묶음 질의 1회로 본다(노드마다 1회가 아님). 시간 기반 네거티브 캐시는 49차에서 받지 않기로 했다(틈을 다시 연다).
- **Q6 → 동의.**

## 51차
- **Q1 파이프 접속 순서 → 반박.** 등록부·최종 경로(Program Files 아래) 검사는 파이프를 열기 전에 한다. 서버 PID 는 파이프를 열어야 얻으므로 그 뒤에 확인하고, 다르면 한 글자도 보내지 않는다.
  "단추를 누른 시각"만 새는 것은 받아들인다.
- **Q2 → 동의.**
- **Q3 Program Files 아래 판정 → 일부 반박, 일부 통합 설계로.** 등록 값은 HKLM 이라 관리자만 바꾼다 — 일반 권한 공격자는 등록부를 "속일" 수 없다(HKCU 는 파이프 이름뿐이고 형식·서버 경로를 확인한다).
  서명 확인(서명자 고정)은 두 프로그램이 함께 지킬 규격이라 이 저장소에서 먼저 넣지 않는다 → 통합프로젝트 변경 제안 후보(상용 인증서는 사지 않으므로 자체 서명 지문 고정 방식).
- **Q4 사설·루프백 주소 경고 → 반박.** NetX 는 같은 PC 에서 도는 프로그램이고 값은 PC 밖으로 나가지 않는다. 단추 문구가 무엇을 넘기는지 이미 적는다.
- **Q5 → 낡음.** 이름 사건은 기록된 짝 주소를 바로 넘기게 바뀌었다(변경 제안 2판). 주소 고르기는 짝 주소가 없을 때만.
- **Q6 32/64비트 등록부 → 반박(시험으로 확인됨).** CI 설치 시험(A28)이 64비트 보기에서 값을 읽어 확인한다. 실기에서도 64비트 화면이 NetX 등록을 읽어 단추가 보였다.
