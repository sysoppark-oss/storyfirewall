## 2. 질문 (공격자 관점 먼저)

**Q1 (L077 장부 빠져나가기)**: 장부는 pid 와 부모-자식 관계로 물려준다. 대상이 자식을 만들지 않고 다른 프로세스에 일을 시키는 순서(예약 작업 등록 후 작업 스케줄러가 실행, WMI `Win32_Process.Create`, COM 서버, 서비스 등록, `explorer.exe` 에 열기 요청)로 파일을 만들면 장부 밖이다. 각 경로의 대안 신호와 드라이버 없이 잇는 방법.

**Q2 (L077 pid 재사용·기한)**: 기한(관찰 5·10·30분) 안에 대상이 끝나고 같은 pid 를 다른 프로세스가 받는 순서. 끝 이벤트를 놓치면(ETW 손실) 남의 파일이 장부에 적힌다. 생성 시각으로 키를 바꾸는 비용과 이득.

**Q3 (L077 양)**: 대상이 작은 파일 수만 개를 만들어 장부(그래프 선)를 부풀리는 순서. 수집기의 프로세스별 초당 상한이 있지만 장부 쓰기도 같은 상한을 지나는지, 장부만 따로 묶기(같은 폴더 N개 → 한 줄)가 필요한지.

**Q4 (L076 알림 단계)**: "최근 30일에 같은 도구 세션 기록이 있으면 작게"는 사기범이 한 번 짧게 연결해 기록을 만든 뒤 다음 날 진짜로 연결하는 순서에 약하다. 사람이 "내가 한 것"이라고 확인한 세션만 작게 하는 쪽과 비교해 달라.

**Q5 (L075 해시 대기)**: 재실행 판단을 해시가 올 때까지 미루면, 해시 계산을 늦추는 입력(아주 큰 파일, 잠긴 파일, 네트워크 경로)으로 120초를 넘겨 "전에 실행됨"으로 떨어지게 할 수 있다. 대기 시간이 지나도 해시가 없을 때 무엇을 하는 게 맞는가(지금은 예전처럼 대상 아님).

## 3. 확인된 것
- 시험: 장부 물려받기·기한·끝(단위), 관찰 대상만 열리는 ledger.get(통합), 해시 대기(재실행 → 대기 → 같은 해시면 아님, 다른 해시면 대상), 서명자로 찾은 원격 도구, Session 0 제외, 자손 우선순위, AI 도구 화면 도우미.
