# 49차 검증 답변 반영 (2026-11-11)

대상: 검증의뢰서 49차 — 이야기 목록 세션 가리기 묶음 처리·말씀 표시·재시작 뒤 엔진 바쁨. 답변: Gemini(4항목). Q3(반복 재시작)·Q6(시계 변경)에는 답이 없었다.

| 항목 | 판단 | 반영 |
| --- | --- | --- |
| 1. 단명 프로세스: 세션이 DB 에도 없을 때 기본 차단(Fail-Safe)인지 시험 | **검증(측정 뒤 결정)** | 지금 규칙은 반대다: 세션을 모르는 프로세스는 **보인다**(A30, 22차 Q6 — 수집 전부터 실행 중이던 프로세스 등 세션을 못 얻은 것을 일반 사용자가 못 보면 자기 PC 의 사건을 놓친다). 기본 차단으로 바꾸면 일반 사용자 화면에서 사건이 얼마나 사라지는지 먼저 재야 한다 → 진단에 "세션 없는 프로세스 노드 수(전체·종료됨·수집 전부터 실행)"를 넣었다. 현재 규칙은 통합 시험(`a30_session_arriving_after_judge_hides_story_without_rejudge` 앞부분)이 고정한다. 수치를 보고 "관리자에게만 보임"으로 바꿀지 사용자에게 묻는다(화면에 보이는 범위가 바뀌는 결정). |
| 2. 세션 없는 프로세스 대량 생성 → DB 조회 폭주, 네거티브 캐싱(3~5초) | **부분 수용(방법 조정)** | 전제 정정: DB 재확인은 사건(이벤트)마다가 아니라 **화면 조회(story.events)마다**, 그리고 요청 등급 이상 사건에 든 노드에만 한다. 그래도 같은 노드를 조회 때마다 다시 묻는 것은 맞다. 다만 시간 기반 네거티브 캐시는 받지 않는다: "세션 없음"을 3~5초 기억하면 그동안 방금 막은 틈(세션 기록이 늦게 온 다른 사용자 프로세스가 보임)이 다시 열린다. 대신 **답이 더 바뀌지 않는 것만** 기억하는 방향: 종료된 지 오래된 프로세스의 "세션 없음"은 확정으로 본다. 먼저 2420f24 뒤 "보임 가리기" 시간과 세션 없는 노드 수를 진단으로 재고, 비용이 실제로 크면 넣는다. |
| 3. 빈 값·템플릿 찌꺼기 퍼징으로 화면 깨짐 확인 | **질문과 다른 답(반박) + 별도 과제로 수용** | Q5 는 말씀 구절이 진단·기록 화면에 들어가지 않는지를 소스 문자열 검사로 고정한 방식이 놓치는 경로를 물었다. 답변은 인시던트 데이터의 빈 값 처리 이야기다. Q5 자체는 미해결로 남긴다(간접 경로: 공용 부품 loadingBox 는 기본이 "구절 있음"이라 새 기록 화면을 만들 때 word:false 를 빠뜨릴 수 있다 → 기본값을 뒤집는 것을 검토). 빈 값·null 주입 시험은 타당한 별도 과제다: 서비스 문자열은 이미 텍스트 노드로만 넣고(sanitize 시험), 이야기 카드의 빈 필드 처리 시험을 추가 과제로 둔다. |
| 4-A. SQLite WAL + 읽기 전용 연결 분리 | **이미 적용(전제 정정)** | DB 는 처음부터 WAL 이고, 읽기 전용 연결을 쓰는 조회 스레드(reads.rs: 오늘 한 일·연결 목록)와 문장·AI 도구 계산 스레드가 이미 있다. 지금 막히는 것은 DB 락이 아니라 **엔진 스레드 하나의 명령 채널**이다(판정 12초 동안 story.events 가 그 줄에서 기다림). |
| 4-B. 이중 버퍼(ArcSwap): 판정이 끝나면 포인터 교체 | **수용(의뢰서 (가)안과 같음)** | 다음 구조 변경으로 확정: 판정이 끝날 때 "조회용 스냅숏"(사건 목록·문장 캐시·가리기에 쓰는 그래프 조각)을 내놓고, 조회 스레드가 그것과 읽기 전용 연결(4-A)로 답한다. arc-swap 크레이트는 들이지 않는다 — 교체가 분당 한 번이라 표준 라이브러리(Mutex 안의 Arc 를 복제해 꺼내기)로 충분하고 의존성을 늘리지 않는다. |
| 4-C. 이벤트 푸시 | **보조로만** | 48차와 같은 판단: 엔진은 Tauri 앱이 아니라 별도 서비스라 파이프 구독(events.subscribe)으로만 밀 수 있다. 푸시는 "새 스냅숏이 나왔다"는 신호로 쓰고(화면이 그때 다시 조회), 데이터 자체는 4-B 스냅숏에서 읽는다. |

덧붙임(자체 검증에서 찾은 것)
- 세션 틈을 재현하려던 통합 시험은 수정 전 코드에서도 통과한다: 시험 경로에서는 기록 반영 뒤 "판정 뒤 정리"가 판정을 다시 돌려 메모리 그래프가 곧 새로워진다. 시험은 끝에서 끝까지의 성질(세션이 DB 에 들어오면 다음 조회에서 숨김)만 고정하고, 2420f24 의 분기 자체를 가려내지는 못한다. 스냅숏 구조로 옮길 때 가리기 함수를 따로 떼어 낡은 그래프를 직접 넣는 단위 시험으로 바꾼다.
