# 45·46차 검증 답변 반영 (2026-11-09)

Gemini 답변(45차 Q1~Q7, 46차 Q1~Q5)을 항목마다 **수용 / 반박(근거) / 검증**으로 정리했다.
대조한 코드는 커밋 fb349c4(v0.1.6) 기준이고, 반영한 코드는 이 문서와 함께 올린 커밋이다.

## 45차

| 번호 | 판정 | 내용 |
|---|---|---|
| Q1 팔레트 이름 위장 | **이미 반영 + 일부 💡** | 제어 문자(RLO 등 BIDI·폭 없는 문자)는 이미 `sanitize`가 지우고 텍스트 노드로만 넣는다(시험 있음). 같은 이름 실행 파일은 11/9 커밋부터 폴더 끝 두 단계를 보조 글자로 보인다. **서명 배지는 💡**: `process.find`가 서명을 돌려주지 않는다. 해시 앞자리는 사용자가 읽기 어렵다고 보고 반박. |
| Q2 경로 차단 우회(복사·링크) | **사실 수용 / 고칠 방법 반박** | 우회 시나리오는 맞다. WFP ALE 의 `FWPM_CONDITION_ALE_APP_ID` 는 실행 이미지 경로로 판정하고, 해시·File ID 조건은 없다(사용자 모드 WFP 로는 해시 차단 불가 — 프로세스마다 해시를 보고 필터를 거는 것은 끊기 기능의 "자손 필터 추가"처럼 사후 대응). 그래서 **대화상자 문구를 사실대로 고쳤다**: "경로로 막으므로, 같은 파일을 다른 폴더로 복사하거나 다른 이름(링크)으로 실행하면 막히지 않습니다." |
| Q3 "오늘" 기한과 절전 | **반박** | "오늘"은 적용을 누르는 순간 자정까지 남은 분을 계산해 `expires: Nm` 로 보내고, 엔진은 받은 시각 + N분을 절대 시각(unix 초)으로 저장한다. 만료는 엔진 주기 tick 이 벽시계로 비교하므로, 절전에서 깨어나면 다음 tick 에 바로 만료된다. 상대 타이머가 아니라 "굳는" 일이 없다. 남는 차이는 적용 뒤 시간대를 바꾸면 "자정"이 옛 시간대 기준이 되는 것 하나(사소, 💡). |
| Q4 스위치 비밀·놓침 | **일부 수용** | 이미 토큰 단위로 정확히 같은지 보고, 대소문자를 무시하고, `=` 앞만 남긴다(`/SILENT /PASSWORD=x` → `/SILENT` 만, 시험 있음). 놓침 지적은 수용해 `--quiet`·`-quiet`·`-passive`·`-silent`(WiX burn 등)를 더했다. Rust·TS 양쪽에 시험을 붙였다(`--quietly` 같은 것은 아님). |
| Q5 연장 반복으로 잠김 | **전제 반박 / 누적 상한 수용** | `emergency.extend` 는 관리자 전용이고 부를 때마다 승인 창이 뜬다. "일반 사용자 + 스크립트 무한 호출"은 성립하지 않는다(api 시험의 관리자 목록에 있음). 다만 "지금부터 하루" 상한은 연장을 거듭하면 끝없이 늘어날 수 있었다. **누적 상한으로 바꿨다: 그 긴급 차단이 걸린 때부터 1440분**(policy_versions.ts 기준). 시험: 20시간 뒤 연장해도 넘지 않음. |
| Q6 PID 재사용 | **이미 반영 / 💡** | 프로세스 고유 ID 는 처음부터 PID + 생성 시각이다. 문제는 생성 시각을 모를 때였고, 45차 1-5 에서 그런 경우 부모를 잇지 않게 했다. "WFP 의 프로세스 시퀀스 번호"는 WFP 에는 없다(추측 아님 — WFP 조건 목록에 없음). Kernel-Process ETW 의 ProcessSequenceNumber 를 키에 더하는 것은 💡 로 둔다(이벤트 판별 필드 확인 필요 — 추측). |
| Q7 팔레트 호버·키 충돌 | **반박(이미 처리)** | 선택은 `mousemove`(실제로 움직일 때만)로만 바뀌고, 키 이동마다 `scrollIntoView({block:"nearest"})`, Esc 는 `dialog.close()` 한 길로만 닫힌다. 마우스를 올려 둔 채 화살표를 눌러도 선택이 튀지 않는다. 디바운스는 키 반복 입력을 늦추므로 넣지 않는다. |

## 46차

| 번호 | 판정 | 내용 |
|---|---|---|
| Q1 색인 쓰기 부담 | **반박(실측)** | 규모 시험(프로세스 노드 2만, 원시 2.8만, 선 3.6만)의 적재 시간: 색인 없음 5,634·5,888ms / 있음 5,848·5,836ms — 차이 약 1.4%, 오차 안이다. 쓰기는 이미 `BEGIN IMMEDIATE` 트랜잭션으로 묶어 넣고(수집 세션), WAL 이다. 배치 큐잉은 이미 있는 구조. |
| Q2 기록 넘치기·속이기 | **수용(넘치기) / 일부 반박(속이기)** | 넘치기: 포트를 바꿔 가며 쏟아내면 1초 묶기를 피해 3,000건 고리가 밀린다 — 맞다. **규칙·프로그램별 누적(필터×프로그램, 2,000가지까지)을 고리와 따로** 두어, 밀려난 것까지 "어느 규칙이 어느 프로그램을 몇 번"이 남게 했다(화면: 차단 기록 › 규칙·프로그램별 누적, 시험 있음). 속이기: 필터 이름은 원래 이름 그대로 따옴표 안에 보이고 종류 라벨은 공급자로 정한다. "등록 주체 서명과 대조"는 WFP 가 필터를 만든 프로세스를 기록하지 않아 할 수 없다(반박). 대신 **"우리 것" 판정을 공급자 키가 아니라 받은 때 우리 정책 필터 목록(엔진 DB)에 있었는지로** 바꿨다. 우리 공급자 키인데 목록에 없으면 "우리 목록에 없는 필터"로 따로 보인다. |
| Q3 공급자 GUID 단정 | **수용(문구)** | 관리자 권한이면 다른 공급자 키로 필터를 넣을 수 있다고 본다(공급자 키는 필터 속성일 뿐 — 추측이 아니라 FWPM_FILTER0 구조상 호출자가 정함). 머리 안내에 "규칙의 주인은 필터에 적힌 공급자로 가립니다. 관리자 권한 프로그램은 다른 공급자를 흉내 낼 수 있습니다"를 넣었다. 줄마다 "(추정)"을 붙이는 것은 읽기를 해친다고 보고 머리 한 번으로 했다. Windows 방화벽 규칙 이름을 방화벽 규칙 저장소(INetFwPolicy2)와 대조하는 것은 💡. |
| Q4 루프백 부담·WFP 밖 차단 | **일부 반박** | 기록하는 것은 **막힌** 연결뿐이라 정상 루프백 통신은 기록되지 않는다(허용 사건은 구독하지 않음). 루프백 막힘이 쏟아지는 것은 Q2 누적으로 덮는다. WFP 밖 차단(확장 프로그램·백신 웹 보호) 안내는 이미 머리에 있고, "확장 프로그램"을 더했다. |
| Q5 실시간 다시 그리기 | **반박(구조)** | React 가 아니라 DOM 직접 그리기다. 막대는 나라·망 각각 상위 6~8줄만 그리고, 집계는 O(n)이다(연결 수천 개도 수 ms — 추측, 실기기 측정은 다음). 지도는 SVG 한 장의 칠만 바꾼다. 대시보드 10초 갱신은 카드가 화면에서 빠지면(`isConnected`) 멈춘다. 쓰로틀링은 갱신 주기(5/15/30초) 자체가 하고 있다. |

  - 머리 안내에 공급자 판별 한계와 확장 프로그램.
