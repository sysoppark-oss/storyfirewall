## 2. 질문 (공격자 관점 먼저)

Q1 (정상 조합 키): ① 키 = `chain:<부모 root_key>><도구 root_key>><띄운 프로그램 root_key 정렬;…>><명령 종류;…>`. 띄운 프로그램이 **줄어드는** 경우(같은 조합인데 이번엔 자식 하나가 아직 안 떴을 때)도 키가 달라져 다시 의심한다 — 오탐으로 보는가, 안전 쪽 오류로 받아들일 만한가. ② 부모가 없는(수집 전부터 돌던) 도구는 부모 "?" — 공격자가 부모를 숨기는 길이 되는가. ③ 서명된 Windows 도구는 root_key 가 "경로|서명자"라 해시가 바뀌어도 같은 키다 — 도구 교체(동일 경로·동일 서명자 갱신)는 의도한 상속이지만, 띄운 프로그램이 **서명 없는** 것이면 file_id(경로·크기·수정시각)로 묶인다. 공격자가 같은 크기·수정시각을 맞춘 다른 내용의 파일로 바꿔치기하면 정상 키를 상속하는가(해시 도입 전 한계). ④ 조합 키는 판정 뷰(최근 창)에서 만든다. 뷰 창 밖(오래된) 자식 실행은 키에서 빠지므로, 창 경계를 넘을 때 같은 사건의 키가 바뀔 수 있는가.

Q2 (재발 판정): ① "높은 장"만 재발로 본다. 조치 뒤 같은 장에서 **새 접속지**(다른 나라·다른 망)가 생겨도 재발이 아니다 — 공격자가 4장에 머물며 접속지만 바꾸면 영원히 조치함으로 남는가. ② 닫힘(사용자 메모)과 조치함의 재발 기준을 같게 둔 것이 맞는가. ③ 재발 알림이 반복되는 순서(되돌림 → 사용자가 다시 닫음 → 되돌림)로 알림 폭주가 가능한가.

Q3 (권한): `story.triage` 는 조회 권한(승인 창 없음) — 일반 사용자 세션이 사건을 닫을 수 있다. 개인 PC 전제이지만, 공격자가 사용자 권한으로 UI 파이프에 접속해 자기 사건을 "닫힘"으로 만들어 알림을 끌 수 있는가. 처리 기록에는 actor 가 남지만 알림은 꺼진다. 판정은 여전히 돌고 재발이면 되돌린다 — 이것으로 충분한가, 아니면 닫기도 승인 창을 거쳐야 하는가.

Q4 (개수 줄): 개수는 사건(판정 결과) 단위, 카드는 같은 판정 묶음(2-9) 단위라 "처리 안 한 사건 81"에 카드는 그보다 적다. 사용자가 혼동할 문구인가 — "사건 81 · 카드 N" 으로 둘 다 보일 것인가.

Q5 (화면 응답): 노트북에서 지켜보기 뒤 목록 전체 다시 불러오기가 10초를 넘었다(이야기 목록 + 오늘 한 일). 지침 "조회 2초 이내"에 어긋난다. 상태 변경 뒤에는 그 카드만 옮기고 목록은 다시 부르지 않는 쪽이 맞는가(진단 diag-26 에서 단계별 시간 측정 예정).
