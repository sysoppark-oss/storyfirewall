## 2. 질문 (공격자 관점 먼저)

**Q1 (ICMP 전송 계층)**: ① 전송 계층 차단은 상태가 없다(ALE 처럼 흐름 단위가 아님). "들어옴 · ICMP · 상대 X 차단"은 내가 X 로 보낸 ping 의 **응답(echo reply)** 도 막는다 — 사용자가 기대한 것과 다른가, 문서화로 충분한가. ② ICMP 오류 메시지(Type 3·11)는 전송 계층에서 보이는가, 아니면 별도 ICMP_ERROR 계층에서만 보이는가 — "ICMP 차단"이 경로 MTU 탐색을 깨는 순서가 생기는가(37차 Q3 결론이 계층을 옮긴 뒤에도 유효한가). ③ 전송 계층 필터는 IPsec·루프백·로컬 전달 경로에서 판정되지 않는 경우가 있는가. ④ 패킷마다 판정이므로 ping 폭주 때 성능 영향.

**Q2 (ACL Sublayer 분리)**: ① 공격자(관리자 아님)가 같은 Provider 아래 Sublayer 를 하나만 지우게 할 수 있는가(삭제 구독은 Provider 단위로 둘 다 알림) ② 옛 판에서 ACL 필터가 주 Sublayer 에 들어가 있는 PC 는 재적용 전까지 옛 순서(예외가 ACL 차단을 뚫음)로 남는다 — 업그레이드 때 다시 걸어야 하는가 ③ ACL 허용이 이제 "표 안의 아래 차단에 대한 예외"로만 뜻이 줄었다. 사용자가 "허용"으로 끊기 차단을 풀 수 있다고 오해하는 화면 순서.

**Q3 (되돌린 뒤 표)**: 서비스 상태(적용·확인됨)와 화면 표가 어긋나는 순서 — 예: 다른 창에서 고급 편집기로 ACL 을 바꾼 직후, 승인 창이 열린 채 기한이 지난 경우, 목록 읽기가 실패한 경우.
